## Standing session rules

1. Read-only diagnostics confirmed by Alex before any build prompt runs.
2. Dry-run + single-item verification before any full batch.
3. **Every batch/backfill ends with a hard reconciliation count** — attempted / stored / errored / skipped, checked against the DB. A "success" with no count is not a success.
4. Long jobs: `nohup` + timestamped logs, `tail -f`.
5. Git from repo root, never `~`. **Repo root is `/Users/alexwhitley/rhemata`** — the `~/Desktop/rhemata` path in older docs is a dead stub from the July 6 folder move.
6. `CLAUDE.md` / `SKILL.md` updated only after a build is confirmed working. (Note: they currently claim the chokepoint is shipped — false; corrected at #3/#14.)
7. Two isolated commits: build separate from docs. **Exception: #1.5 is a one-shot recovery checkpoint of already-messy uncommitted work — clean slicing doesn't apply retroactively; rule 7 resumes from the next change.** (Alex doesn't use git history for recovery — restore-from-backup is the real mechanism — so clean slicing is low-value here anyway.)
8. No bundling. Own-session items stay own-session.
9. Prompts written fresh each session against the current codebase.
10. **Freeze new-source ingests through unconverted scripts** during the chokepoint period (through #13) — each one widens the backfill.
11. **Answers paraphrase and cite; they never quote freely.** Permanent product posture. Verbatim text reaches users only through the verified quotes surface (the quote track, #21–25). No verification of the token stream will ever be needed because the stream never carries quotes. Clarification (2026-07-10): this rule is NOT a copyright-permission gate — quotes are, and always were, a universal UX feature, not a copyright-safety layer (see Decision 2 and the 'License-gating quotes' entry under Killed). The reason the stream never carries quotes is ACCURACY, not legal risk: nothing inspects the token stream, so nothing can guarantee a model-emitted 'quote' is what the teacher actually said or is attributed to the right teacher. Rhemata's differentiator is stated as a structural 'cannot' ('a quote cannot appear unless the teacher literally said it') — an instruction to an LLM can only ever deliver 'probably won't,' never 'cannot.' Only the verified-quotes-table architecture (Q1-Q5) delivers 'cannot,' because it removes quote generation from the model entirely: quotes are extracted and machine-verified at ingest, stored, and served as retrieved rows the UI renders — never generated at answer time. This is why the stream stays paraphrase-only PERMANENTLY, not as an interim state pending Q1-Q5: allowing the model to also emit quote-formatted text would create a second, unverifiable quote channel indistinguishable to users from the verified one, and a single fabricated quote in that channel poisons trust in every real quote in the table. Retrieval by keyword/taxonomy for quotes is native to this design — quotes inherit their source document's topic_tags and FTS, same as any other row.
12. **Shipping a fix includes correcting the record in the same session.** When code changes behavior, the description of that behavior — in PLAN.md, rhemata-status.md, CLAUDE.md, wherever it lives — is corrected before the session ends, not deferred to a later cleanup pass. A session must never end with shipped code and a stale description of it. Drift enters in the gap between "code changed" and "words caught up"; this rule closes that gap to zero.
