## This session (2026-07-13) — live data-integrity fix, not on the numbered roadmap

Found during #9's read-only diagnostic scoping (alignment-guarantee question): the `chunks` table had no uniqueness constraint on `(document_id, chunk_index)`, and duplicate rows already existed in live, `shown` data. Phased as its own real-writes session with a hard stop for classification before any deletion.

- **Phase A (read-only classification):** enumerated every colliding `(document_id, chunk_index)` group table-wide — **186 documents, 9,168 colliding pairs, 18,336 rows**, not scoped to any single source. Classified each group IDENTICAL (byte-identical content, safe to dedup) vs DIVERGENT (real distinct text sharing an index, do not delete blindly): **9,128 IDENTICAL groups, 40 DIVERGENT groups** (all Derek Prince, all `chunk_index=0`, one per doc — an April-22 ingest with a stray leading `---` delimiter vs a cleaner May-16 re-ingest of the same teaching). Embedding-mismatch check on IDENTICAL groups: 2,332/9,128 had non-bit-identical stored embeddings for identical text, sampled cosine similarity 0.999987–0.999999 — consistent with known OpenAI embedding-call floating-point non-determinism, not corruption; dedup confirmed lossless.
- **Phase B (dedup, real writes, single transaction, Alex-approved 2026-07-13):** fresh drift-guard recount matched Phase A exactly before touching anything. Deleted 9,128 IDENTICAL rows (kept lowest id) + 40 DIVERGENT rows (kept the later-`created_at`/clean-extraction copy, deleted the earlier — zero created_at ties found, so no ambiguous cases). **9,168 rows deleted total, committed once.** Verified off the live DB post-commit: zero `(document_id, chunk_index)` collisions remain table-wide; spot-checked 6 documents directly (STEPBible's "LSJ Greek Lexicon — Extended Entries": 10,058→5,324 chunks, now exactly 1:1 with distinct indices; 2 Precept Austin word studies: exactly halved; all 3 sampled Derek Prince docs: exactly 1 `chunk_index=0` row remaining, later timestamp, no leading `---`).
- **Phase C (guardrail):** migration `061_chunks_unique_chunk_index.sql` — `ALTER TABLE chunks ADD CONSTRAINT chunks_document_id_chunk_index_key UNIQUE (document_id, chunk_index)`. Applied cleanly (zero errors, since Phase B had already zeroed out every collision). Confirmed live via `pg_constraint` catalog query, not trusted from apply-script output. **Side effect:** `ingest_lexicon.py`'s existing `INSERT ... ON CONFLICT DO NOTHING` is now functional for the first time — previously inert, since no constraint existed for a conflict to fire against.
- **Root cause, not fixed this session (by design):** the duplication had two independent origins, neither of which is the `shared_ingest.py` `on_existing="reuse"` hook itself (that hook has genuinely never been exercised by any converted script — see Open Flag #3 below for the corrected framing). Precept Austin's and STEPBible's duplication trace to each unconverted script's *own* pre-chokepoint reuse/resume logic (Precept Austin's skip-check keys on an `excerpts` row, not on chunks — 398/2,176 PA docs currently have no excerpt and are still exposed to this on any re-run; STEPBible's resume-by-count logic paired with the now-newly-functional-but-previously-inert `ON CONFLICT DO NOTHING`). Derek Prince's duplication predates the current `ingest.py`/`shared_ingest.py`/dedup-guard architecture entirely (chunk timestamps Apr 22–May 16, `full_text IS NULL` on all 40 docs) — the code that produced it no longer exists to diagnose further, and a live re-run of today's `ingest.py` would skip these files via the current `already_ingested()` guard. The constraint added this session makes the *symptom* (silent duplicate rows) structurally impossible everywhere, but does not fix any script's own reuse-check logic — that remains #11's job.
- **Commits:** migration `061` committed separately from this doc correction, per Standing Rule 7 (build separate from docs) — SHAs in "Standing Carve-Out" section below once pushed.
